# Own Residential Units and Memberships in Convex for the MVP

Unidades residenciales, Apartamentos and Membresías live only in Convex (`residentialUnits`, `apartments`, `memberships`, plus a `superadmins` table for the platform role). A Membresía is created by an Administrador (or the Superadmin, for a unit's first Administrador) with an email and a Rol; it stays `pending` until a Usuario whose WorkOS-verified sign-in email matches signs in, when `memberships.activatePending` links it to that Usuario. Every function scoped to a unit takes the caller's `membershipId` and goes through `Memberships.requireMembership(membershipId, roles)`, which checks that the Membresía is active, belongs to the caller and has an allowed Rol; the function then reads only rows of that unit. The frontend carries the active Membresía in the URL (`/app/m/$membershipId/...`), so switching units is a navigation, not a token refresh.

This defers the project owner's choice, recorded in the map (#1) and researched in #3, of modelling each Unidad residencial as a WorkOS Organization. That model needs environment roles, an organization per unit and token claims configured in the WorkOS dashboard (ticket #17, a human task), while each linked worktree runs on a disposable unclaimed WorkOS environment. Apartamento and Tipo de ocupación would have lived in Convex anyway, and the research already advised authorizing against the local Membresía rather than the token's `role` claim. Keeping Convex as the single source of truth lets the MVP run end to end without that setup and without webhook ordering concerns.

Moving to WorkOS Organizations later is additive: add `externalOrganizationId` to `residentialUnits` and `externalMembershipId` to `memberships`, create them through the WorkOS API when a unit or Membresía is created, sync `organization_membership.*` events like ADR 0003 does for users, and keep `requireMembership` as the authorization boundary. Invitation emails are not sent yet; the Administrador shares the app link until the transactional email provider (#16) is configured.
